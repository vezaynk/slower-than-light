# @stl/campaign

This package writes the catalog (`@stl/catalog`) out as files in two halves:

- **The body**, which is ftl.dat's own XML: blueprints, sectors, events, lists and achievements. `@stl/totallynotftl` packs it into `totallynotftl.dat`.
- **The gap**, a Slipstream mod (`mod/` and `base.ftl`). It holds the rules the real FTL keeps in its executable rather than in `ftl.dat`. The setup screen always loads it last, over whatever base game is chosen. With the real `ftl.dat`, it supplies the same hard-coded rules.

To regenerate both halves:

```sh
pnpm campaign:xml   # writes mod/ and base.ftl
```

## The gap's own dialect

The gap uses Slipstream's `mod:` patching (`findName`, `findLike`, `mod-overwrite`, `mod-append`). Some of its
tags are Hyperspace's. The others exist only in this project, because neither vanilla FTL nor Hyperspace has a
tag for the rule. The reader for all of them is `packFromFtl` in `@stl/pack` (`src/ftl.ts` and `src/parse.ts`).

| Tag                                                                                                                                                                                                                                                                                          | File                                                | What it sets                                                            | Vanilla FTL                              | Hyperspace                                                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Crew stats on `crewBlueprint`: `maxHealth`, `moveSpeedMultiplier`, `repairSpeed`, `damageMultiplier`, `suffocationModifier`, `fireDamageMultiplier`, `fireRepairMultiplier`, `bonusPower`, `hasDeathExplosion`, `oxygenChangeSpeed`, `detectsLifeforms`, `resistsMindControl`, `powerEffect` | `blueprints.xml.append`, `dlcBlueprints.xml.append` | What each race does                                                     | In the executable                        | Same tag names, but on `<crew><race name="…">` in `hyperspace.xml`. Here they patch the race's `crewBlueprint`, so a dat carries them with no second file. `parsePack` also reads them on a `<race>`. |
| `customStore`                                                                                                                                                                                                                                                                                | `gap.xml`                                           | Store stock, prices and shelf sizes                                     | In the executable                        | Same tag (`<customStore id="…">`, `hyperspace.xml`)                                                                                                                                                   |
| `rewards`, `rewardScaling`, `resourceRewards`                                                                                                                                                                                                                                                | `gap.xml`                                           | Scrap and resource bands by reward level and sector                     | In the executable                        | Same tags (`<rewards>`, `hyperspace.xml`)                                                                                                                                                             |
| `shipBlueprint` › `surrender chance min max`                                                                                                                                                                                                                                                 | `gap.xml`                                           | Each faction's default surrender chance and its hull band               | In the executable                        | **None.** Hyperspace's `<surrender/>` is an event action that triggers a surrender; it does not set the odds.                                                                                         |
| `shotGap` on `weaponBlueprint`                                                                                                                                                                                                                                                               | `blueprints.xml.append`                             | Seconds between shots in one volley                                     | Implied by the weapon's animation timing | **None**                                                                                                                                                                                              |
| `shipClass name class blueprint pirate`                                                                                                                                                                                                                                                      | `gap.xml`                                           | Which blueprint an event's ship class becomes, and its pirate variant   | In the executable                        | **None**                                                                                                                                                                                              |
| `emptyBeacon`                                                                                                                                                                                                                                                                                | `gap.xml`                                           | The sentences for a quiet jump, by sector                               | In the executable                        | **None**                                                                                                                                                                                              |
| `beaconEvents` › `startEvent`, `finishEvent nebula`                                                                                                                                                                                                                                          | `gap.xml`                                           | The start and exit beacon events a sector opens when it names none      | Fixed event names in the executable      | **None.** Hyperspace has per-event hooks but no sector default.                                                                                                                                       |
| `achievement` › `condition`                                                                                                                                                                                                                                                                  | `achievements.xml.append`                           | What earns each achievement, as `<value name min>` with `any` and `not` | In the executable                        | **None.** Hyperspace achievements are unlocked by event actions.                                                                                                                                      |
| `achievement` › `slug`, `sectorDescription` › `note`                                                                                                                                                                                                                                         | `achievements.xml.append`, `sector_data.xml.append` | Reference text: an achievement's wiki slug, and a sector's facts        | n/a                                      | **None.** The pack carries these; no game rule reads them.                                                                                                                                            |

So the dialect adds the rules a mod could otherwise only change by patching the executable: how ships
surrender, what a ship class spawns, the volley rhythm, the quiet beacons, the sector's default start and exit
events, and achievement conditions. Hyperspace already has tags for crew stats, stores and rewards, and this
project uses its names for those.

The rest of Hyperspace's `hyperspace.xml` is not read yet. No code here handles `loadEvent`, `jumpEvent`,
`statBoost`, custom ships or the other features, though a `.ftl` that patches `hyperspace.xml` still applies. The
root README tracks Hyperspace compatibility.
